# ESP microphone repair — 2026-10-13

## Measured before changes

- Device readout: ESP32-S3 rev v0.2, MAC 68:ee:8f:dd:31:3c, embedded 4MB flash.
- Full flash backup: `/tmp/opencode/esp-before-fix.bin` (4,194,304 bytes).
- Real Pi `/esp/record?seconds=3` capture: 144025 stereo frames, L=R throughout,
  min -32768, max 32766, RMS 18913, successive-sample roughness 1.403.
- USB telemetry instead reported 24-bit RMS 125894–609633. Nonzero bytes alone
  were therefore not proof of usable audio.
- Existing source casts `(rawBuffer[i] >> 8)` to int16, keeping low 16 bits of
  a 24-bit sample. Correct conversion keeps the signed top 16 bits (`>>16`).
- Running flash contains the diagnostic strings in the read-only reference
  `/home/solrahk/Arduino/esp32s3_mic_telemetry/esp32s3_mic_telemetry.ino`.
  That reference has the same conversion fault. Deploy only from the canonical
  repo, not that alternate source.
- Browser live dashboard: AudioWorklet context running, 305152 rendered frames,
  52643 underrun samples, no JS exceptions. Audible quality not yet verified.
- Thermal temporarily lost I2C address 0x33 before any Pi change. Later recovered
  unaided: valid frame 5137 at 1.85 FPS. No Pi service restart or edit performed.

## Live verification and deployment

  source now retains WiFi retry, rate-limited MQTT retry, retained wire-format
  announcement, and 24-bit diagnostics. Disabled USB recorder was not imported.
- Corrected PubSubClient boolean success handling and format-publish retry.
- Actual flash header mismatch caused first deployment to reboot: `4096k`
  hardware versus `8192k` image. Use `board_upload.flash_size = 4MB`, NOT
  `board_build.flash_size`. Successful upload hashes verified by esptool.
- Local reference firmware.bin matches original flash application bytes exactly.
  Aligned Arduino framework to 2.0.17 (PlatformIO espressif32 7.0.1).

  Clearing ONLY that station (`iw dev wlan0 station del 68:ee:8f:dd:31:3c`)

  `pig/s3-mic-01/audio/fmt`; serial reports all three links connected.
