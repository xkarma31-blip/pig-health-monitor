## Findings — severity order

1. **High — The documented P release workflow does not exist.**  
   **`revision-p/START_HERE.md:38–41`; `verify_revision.sh:8–19`**  
   START_HERE instructs users to run `verify_revision_p.sh` followed by `package_revision_p.sh`, but neither file exists in this directory. The existing verification runner explicitly refuses P, and its pipeline does not invoke `probe_split_boss_concept.py`. Only an O packaging script is present.  
   **Impact:** P’s passing saved summary is not a reproducible, coherent release procedure. Following the supplied instructions fails before verification or packaging. This is a release blocker, not a mesh defect.

2. **Medium — The P closure gate validates counts, but not the identity or coverage of the tests.**  
   **`summarize_verification.js:31`**  
   The gate does not require the expected part names, stations, hardware roles, lift distances, or intersection-map keys. For example, `Object.values({}).every(...)` passes, so two shaft records and six hardware records with empty intersection maps satisfy those portions of the gate. Duplicate seat or lift records also satisfy their count checks. Fresh main-part hashes do not prove that those parts received the intended tests.  
   **Impact:** `supplementary_closure_gate: true` can overstate actual coverage. Require the exact expected test identities and finite, nonnegative measurements, including both `main_tub` and `main_lid` intersection values. Missing regression tests should cover empty maps, duplicated stations and omitted hardware roles.

3. **Medium — Support is configured, but its presence is not a P acceptance criterion.**  
   **`slice_revision.sh:18–20`; `summarize_verification.js:48–54,73`**  
   The slicer correctly enables buildplate support for the P main tub. However, the summary merely records `support_enabled`; it never requires it to be `1`. Nor does it verify that support toolpaths were generated beneath the ears. An unsupported slice with fresh hashes, nonempty toolpaths and no matching warning can still pass.  
   **Impact:** The specific manufacturing correction described in `revision-p/START_HERE.md:33–35` is not protected against regression. At minimum, gate the intended support configuration; separately verify actual support generation rather than treating configuration alone as proof.

4. **Low — P’s own closure evidence falsely labels installed geometry as an uninstalled experiment.**  
   **`probe_split_boss_concept.py:1–3,15,108–116`**  
   P mode deliberately imports and tests the already-installed P ears, but still emits `"experiment only; not installed or released geometry"`. “Not released” is consistent with candidate status; “not installed” is not. The limitations also say there is no full installed assembly audit without distinguishing this local probe from the separately supplied assembly checks.  
   **Impact:** Release evidence contradicts the candidate documentation and obscures what was actually tested. This should be corrected before promotion.
